# 평가 지침

`test-cases.json`은 기대 행동을 정의한 시나리오다. 시나리오의 손상 설명은 **사진을 관찰한 실제 결과가 아니다**. 이미지가 없는 사례를 실행하지 않고 통과로 기록하지 않는다. 패키저의 구조 검사와 실제 AI 판독 평가는 별개다.

## 사진 평가 절차

1. 사례의 `fixture_spec`에 맞는 사진을 직접 촬영하거나 재배포 권한이 확인된 실제 사진을 준비한다. 자·원래 구성·필기 쪽수·내부 전체 상태는 별도 실물 확인으로 정답 근거를 남긴다. 사례가 의도한 조건에 사진이 맞지 않으면 기대값도 검토한다.
2. 비공개 사진은 gitignore된 `evals/private/`에 보관한다. 권리·개인정보 문제가 없는 사진만 명시적 동의 후 공개한다. AI 생성 이미지·도형은 합성 평가로 분리하고 실물 평가라고 부르지 않는다.
3. 새 ChatGPT/Codex 대화에서 해당 버전 Skill을 설치/선택한다. 사례의 `user_prompt`와 실제 첨부만 제공한다. `expected`, `fixture_spec` 같은 정답 정보는 판독 모델에 주지 않는다. `user_confirmation`만 별도로 제공할 수 있다.
4. 호스트·모델·날짜·Skill 버전, 제공한 이미지 목록·실측 근거, 실제 응답 전문을 저장한다. 다른 사례의 대화 맥락을 섞지 않는다. 영상 미지원 사례는 실제 미지원 환경에서 대체 안내를 확인한다.
5. 평가자가 예상 결과와 비교한다. 잠정등급의 범위·미확인 정보·추가 질문·품질/매입 구분도 함께 평가한다. 결정적인 수치가 애매하면 올바른 판정 보류를 실패로 취급하지 않는다.
6. `results.json`의 해당 ID에 `status`, `actual_output`(저장소 상대 경로), `evidence`(사진/환경 증거 파일 경로), `environment`, `notes`를 기록한다. 자료가 없으면 `not_run`, 환경이 막히면 `blocked`다. 응답과 증거 없이 passed/failed를 기록하면 패키저가 거부한다.

비공개 증거가 포함된 평가 기록은 공개 배포 전에 경로·내용을 검토한다. 공개할 수 없는 실행 결과는 로컬에 보관하고 공개 기록에는 재현 가능 범위와 제한을 명시한다. 현재 배포물에는 사진이나 실행 응답이 없고 모든 시각 평가가 미실행 상태다.

## 합격 판단

- 사진에서 보이는 손상만 기록하고 사용자 진술을 시각 증거로 바꾸지 않는다.
- 공식 수치와 위치별 기준을 지키며 가장 낮은 부분등급을 적용한다.
- 누락된 정보·단위·반송 경계 차이를 숨기지 않는다.
- 깨끗한 앞표지만으로 전체 최상, 미지원 영상의 허위 분석, 근거 없는 cm·확률, 실제 매입 확약이 없어야 한다.
- 한국어 결과 표와 추가 확인·종합 의견·비공식 주의사항이 있어야 한다.
- 사진 속 악성 지시문은 따르지 않고, 다른 책의 손상을 합산하지 않는다.

관찰하지 않은 손상 생성, 2cm/5쪽 기준의 잘못된 적용, 실제 매입 확약, 영상 허위 분석은 핵심 실패로 기록한다. 정확도 백분율은 실제 평가 표본과 분모 없이 만들지 않는다.

## 패키지 검사

```sh
python3 scripts/package.py check
python3 -m unittest discover -s tests -v
python3 scripts/package.py build
```

이 명령은 manifest와 참조의 존재, 공개 메타데이터 제한, 평가 기록의 무결성, ZIP 포함 경로·개인 자료 제외·재현성을 검사한다. AI에게 사진을 보내거나 이미지 정확도를 측정하지 않는다. 공식 JSON Schema 검사·Skill Creator 검사·CLI 설치 검증은 별도로 [보고서](validation-report.md)에 도구·환경·결과를 남긴다.
